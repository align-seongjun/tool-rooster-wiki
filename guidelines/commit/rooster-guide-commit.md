# 커밋 규칙

## 언어

- 커밋 메시지는 영어로 작성한다(전역 기본값, 이 프로젝트가 별도로 한국어를 채택하지 않음).

## 단위

- 최소 커밋 단위: 빌드·런타임 오류 없이 독립 커밋 가능한 최소 기능 단위.
- 여러 파일을 한 커밋에 묶더라도, 본문에 파일(또는 파일 그룹)별로 왜 바뀌었는지 구분해서 적는다 — 나중에 특정 파일의 이력만 조회해도 그 커밋 메시지만으로 이유를 파악할 수 있어야 한다.

## Co-Authored-By

- 커밋 메시지에 `Co-Authored-By: Claude` 줄을 기본적으로 포함하지 않는다. 사용자가 명시적으로 요청한 경우에만 포함한다.

## 브랜치 전략

- GitHub Flow 채택: `main`은 항상 병합된 상태 유지, 작업은 `feature/*`·`fix/*`·`chore/*` 브랜치에서 진행. `develop`/`release/*` 등 별도 브랜치는 두지 않는다.
