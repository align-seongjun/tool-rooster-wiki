# Phase 6 — GUI 스파이크

**목표**: 정적 HTML+JS 페이지에서 `fetch()`로 로컬 API를 직접 호출해, 읽기 경로와 간단한 쓰기 경로를 왕복 검증한다 ([gui-spike 아키텍처](../../architecture/gui-spike/rooster-arch-gui-spike) 참조). 완성된 GUI 제공이 목적이 아니라 API 설계 검증이 목적이다.

---

## 작업 항목

1. 정적 페이지에서 게임/숙제 목록 `fetch` 후 렌더링 (읽기 경로)
2. 게임 등록 폼 → API 호출 (쓰기 경로)

---

## 완료 기준

- 엔진을 `serve`로 기동한 상태에서 브라우저로 정적 페이지를 열어, 실제 엔진 데이터가 화면에 표시되는 것을 확인
- 폼으로 게임을 등록하면 CLI `game list`에서도 동일하게 조회됨 (왕복 검증)
