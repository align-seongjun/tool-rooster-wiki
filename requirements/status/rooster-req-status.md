# 엔진 상태 확인

## 개요

트레이 아이콘은 "떠 있다"는 수동적 신호일 뿐이라 사용자가 놓치기 쉽다. 이 프로그램의 존재 이유가 "마감을 놓치지 않게" 하는 것인 만큼, 엔진이 조용히 죽어있는 상태가 최악의 실패 모드다. `status` 커맨드로 엔진 생존 여부를 능동적으로 확인할 수 있게 한다.

## 기능 요구사항

### FR-STATUS-001: 엔진 상태 조회
- **우선순위**: P0
- **설명**: 사용자는 `status` 커맨드로 엔진이 정상 동작 중인지, 스케줄러 루프가 실제로 도는지 확인할 수 있다.
- **수용 기준**: `status` 실행 시 엔진 상태, 가동 시간, 마지막 스케줄 체크 시각, 등록된 게임/숙제 수, 최근 알림 이력, DB 경로, API 포트가 출력된다.

### FR-STATUS-002: "떠 있지만 멈춰있는" 상태 탐지
- **우선순위**: P0
- **설명**: 프로세스 생존과 스케줄러 루프 동작은 별개 문제다. "마지막 스케줄 체크 시각"이 비정상적으로 오래됐다면 이를 구분해 인지할 수 있어야 한다.
- **수용 기준**: 마지막 스케줄 체크 시각이 함께 표시되어, 프로세스는 떠 있으나 루프가 멈춘 상태를 시각 차이로 판단할 수 있다.

## 제약사항

- 트레이 아이콘은 보조 수단일 뿐 — `status` CLI 조회가 1차 확인 수단 ([lifecycle](../../architecture/lifecycle/rooster-arch-lifecycle) 참조)
