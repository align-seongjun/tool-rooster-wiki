# 엔진 생명주기 (자동시작/재시작/status)

## 개요

엔진의 자동시작·크래시 재시작은 OS 네이티브 서비스 매니저에 위임하고, "조용히 죽어있는" 상태를 `status` 커맨드로 능동 탐지한다.

## 결정 사항

- **자동시작 + 크래시 재시작**: 커스텀 워치독을 직접 구현하지 않고 OS 네이티브 서비스 매니저에 위임 — macOS: launchd, Ubuntu: systemd, Windows: Task Scheduler/Windows Service. 각 OS가 이미 검증된 재시작 정책을 제공하므로 자체 구현 대비 신뢰성이 높음.
- **가시성 문제 대응**: 트레이 아이콘은 "떠 있다"는 수동적 신호일 뿐이라 사용자가 놓치기 쉽다. 이 프로그램의 존재 이유가 "마감을 놓치지 않게" 하는 것인 만큼, 엔진이 조용히 죽어있는 상태가 최악의 실패 모드 → 트레이 아이콘 외에 `status` CLI 커맨드로 "마지막 정상 동작 시각"을 능동적으로 확인할 수 있게 함.

## 제약사항

- 3개 OS의 서비스 등록 절차(launchd plist, systemd unit, Windows 서비스 등록)는 플랫폼별로 다름 — Phase 5(엔진 생명주기)에서 각각 구현
- `status`가 보여줄 "마지막 스케줄 체크 시각"은 프로세스 생존과 스케줄러 루프 동작을 구분하기 위한 핵심 필드 ([status 요구사항](../../requirements/status/rooster-req-status) 참조)
