# ADR-001: 엔진/CLI 단일 바이너리 통합

- **상태**: Accepted
- **일자**: 2026-08-13

## 배경

엔진(백그라운드 상주 프로세스)과 CLI(사용자 커맨드)를 어떻게 나눌지 결정해야 했다. `docker`/`dockerd`처럼 별도 바이너리로 나누는 방식이 대표적 선례다.

## 결정

단일 바이너리 + 서브커맨드 구조를 채택한다. `rooster serve`가 엔진 모드로 동작하고, 나머지 서브커맨드(`add`, `list`, `status` 등)가 CLI 모드로 동작한다.

## 검토한 대안

- **`docker`/`dockerd` 패턴(바이너리 분리)**: 역할이 코드 레벨에서 명확히 분리되지만, 바이너리를 둘로 나누면 빌드/서명/배포 부담이 배가된다. 개인/소규모 배포 프로젝트 규모에는 과하다고 판단.

## 결과

- 배포 아티팩트가 하나로 단순해짐
- `main.rs`의 서브커맨드 디스패치가 엔진/CLI 두 역할을 모두 감당해야 함 (관련: [architecture overview](../architecture/overview/rooster-arch-overview))
