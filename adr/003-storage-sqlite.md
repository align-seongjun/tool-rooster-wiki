# ADR-003: 데이터 저장소 SQLite 선택

- **상태**: Accepted
- **일자**: 2026-08-13

## 배경

게임/숙제/완료 이력을 저장할 방식을 결정해야 했다. 데이터 규모가 커질수록(다중 게임/캐릭터, 완료 이력 등) 단순 평문 파일보다 구조화된 저장소가 유리해진다.

## 결정

데이터 저장소로 SQLite를 채택한다.

## 검토한 대안

- **JSON/TOML 평문 파일**: 벌크 인서트의 원자성 보장이 없어 중간 실패 시 파일 손상 위험이 있고, "마감 임박 숙제만" 같은 필터링을 직접 구현해야 한다.

## 결과

- 트랜잭션, WAL 모드(동시 읽기·쓰기), 컬럼 제약조건 기반 무결성을 확보
- rusqlite(bundled feature)로 별도 시스템 SQLite 설치 없이 임베디드 동작 ([tech-stack](../architecture/tech-stack/rooster-arch-tech-stack) 참조)
- 필드 추가 시 마이그레이션 관리가 필요
